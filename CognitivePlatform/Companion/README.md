# Axiom read-only companion

The existing CP Development API serves `/companion`, a responsive browser reader. Its public shell contains no workspace data. Every `/api/companion` data request requires a separate `X-Companion-Key` credential. This feature defaults to disabled and rejects non-Development environments. No Production configuration or data is changed.

Configure `Companion:Enabled`, `Companion:ClientKeySha256` (the SHA-256 hex digest of a dedicated 32–256 character credential), and `Companion:Workspaces` entries containing `Id`, `Label`, and an absolute `RootPath`. Publish only explicitly selected original Markdown roots. The browser credential is held in session memory, cleared from the input after connection, and never placed in a URL or persistent browser storage. Remote connections require HTTPS; loopback HTTP is permitted for local testing. Revoke access by disabling the feature, changing the credential digest, or removing the root. Normal deployment remains disabled until an operator configures an authorized root and transport.

The server reads current saved `.md`/`.markdown` files directly. It never changes Markdown, metadata, recovery state, or domain stores and has no mutation endpoints. Unsaved desktop buffers are not published. Reads include a logical UTF-8 SHA-256, read timestamp and canonical Axiom document ID when present. Preview hides the canonical marker, disables raw HTML, and omits active URLs/images; source view preserves the original text. Task state is displayed as read-only text.

Workspace trees and literal search are bounded: 16 configured workspaces, 2,000 directories, 1,000 Markdown files, 1 MiB/200,000 characters per document, 128 files/8 MiB per search batch, two concurrent operations and a ten-second cancellation deadline. UTF-8 and BOM-marked UTF-16 are supported. Linked/reparse paths, hidden paths, traversal and non-Markdown reads are rejected. Search continuation is explicit; changing source inventory can change ordering, so restart a search to refresh the inventory.

Disconnect and page closure clear the credential and displayed content. Unavailable service states identify the last displayed snapshot as stale; refresh reads current saved source. The shell uses no-store responses, a restrictive CSP, no-referrer policy and no external assets. It creates no editable synchronized copy or offline cache.

Verification uses isolated Kestrel hosts and synthetic workspaces, not the normal CP host or user data. `CompanionControllerTests` covers authentication/revocation, disabled/Production rejection, source immutability/freshness, traversal, safe rendering, Unicode, bounds and pagination. `POCs/CompanionBrowserFixture` supports actual browser checks. Phone-viewport testing does not replace physical phone, HTTPS deployment, screen-reader or human acceptance. Classification/relationship context and stable cross-batch inventory remain follow-up implementation work; no metadata integration is claimed.
